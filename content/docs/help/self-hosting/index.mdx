Omni products are designed to run on your infrastructure. No vendor lock-in, no cloud dependency — your data stays yours. See our [Ethos](/ethos) for more on why sovereignty matters to us.

## Run it with one command

The fastest way to stand up an Omni product on your own machine is [**run**](/products/run), the universal self-hosting CLI. One command pulls the images, generates secrets, wires a reverse proxy with trusted local HTTPS, and waits for every service to report healthy. To contribute instead, [Tilt](https://tilt.dev) brings up the full source with live reload.

<RunPaths appName="Runa" slug="runa" />

Swap `runa` for any app in the [catalog](/products/run/catalog), or point `run` at your own Compose file, [recipe](/products/run/recipes), or image. Prefer to drive Docker Compose, Kubernetes, or a binary directly? Those paths are below.

## Binary Installs

Some products ship as standalone binaries and don't require Docker or Kubernetes.

### Synapse

[Synapse](/products/synapse) runs as a full stack (gateway + API + dashboard) via Docker Compose, or the gateway alone as a standalone binary:

```bash
# Full stack (Docker Compose)
git clone https://github.com/omnidotdev/synapse-stack.git
cd synapse-stack
cp .env.example .env.local
# Set required values (DB_PASSWORD, AUTH_SECRET, GATEWAY_SECRET, ENCRYPTION_KEY)
docker compose --env-file .env.local up -d

# Gateway only (from source)
git clone https://github.com/omnidotdev/synapse-gateway.git
cd synapse-gateway
cargo build --release
# Binary at target/release/synapse
```

Prebuilt gateway binaries for Linux (x86_64, aarch64) and macOS (Apple Silicon) are available on the [releases page](https://github.com/omnidotdev/synapse-gateway/releases).

See the [Synapse self-hosting guide](/products/synapse/self-hosting) for full configuration and environment variable reference.

### Omni Terminal

[Omni Terminal](/products/omni-terminal) runs in the browser via the `serve` subcommand. The WASM frontend is embedded at compile time:

```bash
# Via package manager (Homebrew, AUR, etc.)
omni-terminal serve

# Or from source
just wasm-build
cargo run -p omni-terminal --release -- serve
```

The server starts on `https://localhost:3000` with an auto-generated self-signed TLS certificate.

| Flag / Env | Default | Description |
|------------|---------|-------------|
| `--host` | `127.0.0.1` | Host address to bind to |
| `-p, --port` / `PORT` | `3000` | Server listen port |
| `--tls-cert` / `TLS_CERT` | (auto-generated) | Path to TLS certificate PEM file |
| `--tls-key` / `TLS_KEY` | (auto-generated) | Path to TLS private key PEM file |
| `--no-tls` | — | Serve plain HTTP (skip TLS) |

Docker is also supported:

```bash
docker build -t omni-terminal-web .
docker run -p 3000:3000 omni-terminal-web
```

See the [Omni Terminal Web docs](/products/omni-terminal/web) for full details including TLS configuration and the npm package.
