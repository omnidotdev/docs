---
title: Broadcasts
description: Send a marketing campaign to an audience
---

A broadcast is a one-to-many marketing send: a subject and body sent to every
contact in an [audience](/docs/core/herald/audiences), optionally narrowed to a
segment. Each recipient's copy is rendered with that contact's own attributes, so
one broadcast personalizes the whole send.

Unlike a transactional send, a broadcast is bulk marketing mail, so it must carry
a one-click unsubscribe and a CAN-SPAM footer. Herald enforces that before it
will send (see the block below and [Compliance](/docs/core/herald/compliance)).

## Create a broadcast

`createBroadcast` targets an audience and stores the campaign as a draft. Pass an
optional `segmentId` (of the same audience) to send only to that segment's
matching contacts:

```graphql
mutation {
  createBroadcast(
    input: {
      name: "January newsletter"
      audienceId: "<audienceId>"
      from: "Omni <news@send.example.com>"
      subject: "What's new, {{name}}"
      html: "<p>Hi {{name}}, here's this month's update.</p>"
      segmentId: "<segmentId>"
    }
  ) {
    broadcastId
    name
    status
    createdAt
  }
}
```

The `from` address must be a [verified sending domain](/docs/core/herald/domains),
and the body may use [Handlebars](/docs/core/herald/templates) tags filled from
each contact's attributes.

## Send it

`sendBroadcast` fans the campaign out to every non-unsubscribed contact in its
audience (matching the segment when set), queuing one message per recipient
through the normal send pipeline. The pipeline's verified-domain and
[suppression](/docs/core/herald/suppressions) gates still apply per recipient.
The payload reports how many recipients were queued:

```graphql
mutation {
  sendBroadcast(id: "<broadcastId>") {
    broadcastId
    queued
  }
}
```

Sending claims the broadcast atomically (`draft` to `sent`), so a repeated or
concurrent `sendBroadcast` is a no-op and contacts are never mailed twice. A
broadcast whose audience or segment matches no one is left in `draft` to retry.

## The compliance block

`sendBroadcast` is **hard-blocked** until the tenant is set up for marketing
mail. A broadcast will not send unless:

- the tenant has a **sender name** and **physical postal address** configured in
  Settings (CAN-SPAM requires a clear sender identity and postal address in the
  footer), and
- [tracking](/docs/core/herald/tracking) is configured, because the one-click
  unsubscribe URL is minted on the tracking host.

If the sender name or postal address is missing, the send is refused with a
message telling you to complete Settings first, and the broadcast stays in
`draft`. Herald then injects the `List-Unsubscribe` header and the compliance
footer (sender identity, postal address, unsubscribe link) into every message.
Broadcasts default to open and click tracking on.

See [Compliance](/docs/core/herald/compliance) for the full set of marketing
requirements. Broadcast and audience mutations require a `full`
[API key](/docs/core/herald/api-keys).
