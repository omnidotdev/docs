---
title: Suppressions
description: The per-tenant do-not-send list that protects sending reputation
---

A suppression is a recipient address a tenant should never send to again.
Herald keeps a per-tenant suppression list and checks it before every send, so a
known-bad or opted-out address is refused at the boundary rather than injected,
bounced, and counted against your reputation.

## What gets suppressed automatically

Herald adds addresses to the list on its own from
[delivery feedback](/docs/core/herald/webhooks):

- **Hard bounces** (a nonexistent mailbox or domain) auto-suppress, since
  retrying can never succeed.
- **Spam complaints** auto-suppress, since the recipient has signalled they do
  not want your mail.
- **One-click unsubscribes** on marketing mail add the address as well (see
  [Compliance](/docs/core/herald/compliance)).

Transient, or "soft", failures (a full mailbox, a temporary reputation or rate
block, greylisting) do **not** suppress: the address is still valid and a later
send can succeed, so suppressing it would lose a real recipient and inflate the
hard-bounce rate your reputation is judged by.

## How the send gate behaves

The suppression check runs before any insert or inject. Its effect depends on
where the suppressed address sits in the message:

- A suppressed **primary recipient** (`to`) hard-fails the send with the
  `suppressed` code (HTTP `422` on REST, a `BAD_USER_INPUT` error on GraphQL).
- A suppressed **`cc` or `bcc`** is silently dropped from that copy so one stale
  address never blocks a message to a valid primary recipient.

Matching is exact but case-insensitive and whitespace-tolerant, so
`Ada@Example.com ` and `ada@example.com` are the same entry.

## Managing the list

Add an address manually (for example a role account you never want to mail) with
`addSuppression`. It is upsert-style: re-adding an existing address just updates
its reason.

```graphql
mutation {
  addSuppression(input: { address: "noreply@example.com", reason: "manual" }) {
    suppressionId
    address
    reason
    createdAt
  }
}
```

Remove an address with `removeSuppression`, for example once a recipient asks to
resubscribe. It is idempotent: removing an address that is not on the list still
reports success.

```graphql
mutation {
  removeSuppression(address: "ada@example.com") {
    address
  }
}
```

Both mutations require a `full` API key (see
[API keys](/docs/core/herald/api-keys)). Browse and search the current list in
the dashboard **Suppressions** page, or query the `suppressions` connection.
