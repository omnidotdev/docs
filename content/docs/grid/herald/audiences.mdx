---
title: Audiences and contacts
description: The marketing contact model behind broadcasts
---

Audiences are Herald's marketing contact model. An **audience** is a named list
of **contacts**, each an address with optional per-contact **attributes** used
as merge data. A **segment** is a saved attribute filter over an audience. A
[broadcast](/docs/grid/herald/broadcasts) sends to an audience, optionally
narrowed to one of its segments.

Transactional sends do not need any of this: they address a recipient directly.
Audiences exist for bulk marketing, where you send to a maintained list.

## Create an audience

From the dashboard (**Audiences**) or `createAudience`:

```graphql
mutation {
  createAudience(input: { name: "newsletter" }) {
    audienceId
    name
    createdAt
  }
}
```

## Add contacts

Add a single contact with `addContact`. `attributes` is free-form JSON merge
data (name, plan, locale, anything a template references). Adding the same
address to the same audience again is idempotent and resolves to the existing
contact:

```graphql
mutation {
  addContact(
    input: {
      audienceId: "<audienceId>"
      address: "ada@example.com"
      attributes: { name: "Ada", plan: "pro" }
    }
  ) {
    contactId
    address
  }
}
```

For a bulk import, `addContacts` takes a list. It is idempotent per address, so
re-running an import is safe: existing `(audience, address)` rows are skipped,
in-payload duplicates collapse to the first occurrence, and syntactically invalid
addresses are dropped so a bad row never seeds the list with an address that only
bounces. The payload reports how many were added versus skipped:

```graphql
mutation {
  addContacts(
    input: {
      audienceId: "<audienceId>"
      contacts: [
        { address: "ada@example.com", attributes: { name: "Ada" } }
        { address: "grace@example.com", attributes: { name: "Grace" } }
      ]
    }
  ) {
    audienceId
    added
    skipped
  }
}
```

### CSV import

The dashboard **Audiences** page can import a CSV of contacts, which maps each
row to `addContacts` under the hood, so the same idempotency and hygiene rules
apply: re-importing the same file adds nothing new, and invalid rows are counted
as skipped.

## Segments

A segment is a reusable filter that selects the contacts in an audience whose
attributes match a predicate. Create one with `createSegment`; the `filter` is a
JSON predicate of the form `{ match: "all" | "any", conditions: [{ attribute, op,
value }] }`:

```graphql
mutation {
  createSegment(
    input: {
      name: "pro-users"
      audienceId: "<audienceId>"
      filter: { match: "all", conditions: [{ attribute: "plan", op: "eq", value: "pro" }] }
    }
  ) {
    segmentId
    name
    createdAt
  }
}
```

Preview how many contacts a segment currently matches with the
`segmentMatchCount` query before you send to it:

```graphql
query {
  segmentMatchCount(segmentId: "<segmentId>")
}
```

Contact and audience mutations require a `full`
[API key](/docs/grid/herald/api-keys). Once an audience is populated, send to it
with a [broadcast](/docs/grid/herald/broadcasts).
