---
title: Compliance
description: One-click unsubscribe and CAN-SPAM requirements for marketing mail
---

Bulk marketing mail is held to rules that transactional mail is not: it must
offer an easy opt-out and identify the sender. Herald builds both into every
[broadcast](/docs/grid/herald/broadcasts) automatically, and blocks a broadcast
until the tenant has supplied what the footer needs.

Transactional sends (`POST /messages`, `sendMessage`) are byte-for-byte
unaffected: none of the mechanisms on this page touch them.

## One-click unsubscribe (RFC 8058)

Every broadcast message carries `List-Unsubscribe` and
`List-Unsubscribe-Post: List-Unsubscribe=One-Click` headers. This opts the
message into one-click unsubscribe: a receiving provider (for example Gmail or
Yahoo) POSTs to the unsubscribe URL directly when the recipient uses the native
unsubscribe control, without loading a browser, so the POST itself is the
opt-out.

The unsubscribe URL is minted per recipient on the tracking host, which is why a
broadcast requires [tracking](/docs/grid/herald/tracking) to be configured. The
target lives at `POST /u/:token`:

- `POST /u/:token` performs the opt-out: it marks the contact unsubscribed and
  adds the address to the tenant's [suppression list](/docs/grid/herald/suppressions),
  so no further mail reaches it.
- `GET /u/:token` renders a confirmation page with an unsubscribe button and does
  **not** opt out. A human clicking the footer link lands here; requiring the
  explicit POST prevents email security scanners that pre-fetch links with a GET
  from unsubscribing recipients who never asked to leave.

The token is HMAC-signed, so it cannot be forged or altered to opt out an
arbitrary address for another tenant.

## The CAN-SPAM footer

Herald appends a compliance footer to the body of every broadcast message (both
the HTML and plain-text parts). The footer carries:

- the tenant's **sender identity** (sender name),
- a **physical postal address**, and
- an **unsubscribe link** to the one-click URL above.

The footer is added after tracking is applied, so the unsubscribe link is never
rewritten through click tracking. It is also stored on the message, so the
dashboard detail view and any resend reproduce exactly what the recipient saw.

## Required tenant settings

Because the footer must carry a real sender identity and postal address, the
tenant must set both before any broadcast can send. Configure them in the
dashboard **Settings** page, or with `updateTenantSettings`:

```graphql
mutation {
  updateTenantSettings(
    input: {
      senderName: "Omni, Inc."
      postalAddress: "123 Example St, Springfield, IL 62704, USA"
    }
  ) {
    tenantId
    senderName
    postalAddress
  }
}
```

Until both `senderName` and `postalAddress` are set, `sendBroadcast` is refused
and the broadcast stays in draft (see
[Broadcasts](/docs/grid/herald/broadcasts)). `updateTenantSettings` requires a
`full` [API key](/docs/grid/herald/api-keys).
