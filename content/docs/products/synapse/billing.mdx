Synapse offers flexible billing through [Aether](https://billing.omni.dev), Omni's billing service. You can bring your own provider keys (BYOK), use managed credits, or combine both.

## Billing Modes

### BYOK (Bring Your Own Key)

Store your own provider API keys in Synapse's encrypted vault. Requests route directly through your provider accounts. You pay providers directly and Synapse charges only for the platform subscription.

Keys are stored per vendor (`openai`, `anthropic`, `google`, ...). Your `openai` key also serves speech-to-text (Whisper), text-to-speech, embeddings, and image generation, since those run on the OpenAI API. A request to a provider you have no key for is refused with `400`.

### Managed Credits

Use Synapse-provided keys with pay-as-you-go pricing. Provider costs are passed through with a 15% margin. No need to manage individual provider accounts.

### Hybrid

Combine BYOK and managed keys. Attach provider keys to specific Synapse API keys, and fall back to managed credits when no BYOK key is available.

## Workspaces

A Synapse subscription belongs to a workspace, and so does every API key. A key's requests count against the plan of the workspace it belongs to: the tier, the monthly request allowance, the API key limit, overage, and the spending limit are shared by every key in the workspace, whichever member created it.

- Keys created from your own dashboard belong to your personal workspace
- Keys created in a team workspace belong to that team. Any member can see the team's keys; creating keys and revoking another member's key require the admin role

## Request Overage

Pro and Team include a monthly request allowance. Requests above it keep working and are billed as overage at the end of each billing period:

- Overage is the number of requests above the included allowance, at the tier's rate ($0.20 per 1K on Pro, $0.10 per 1K on Team), charged pro rata (one request over Pro costs $0.0002)
- The charge is added to the subscription's renewal invoice. Any credit balance on the billing account is applied first, and the remainder is charged to the payment method on file
- The request count resets at the start of each billing period
- Overage is bounded by the hard spending limit. Paid plans start with a default limit of $100 of overage per month on Pro and $500 on Team. Once the next request would exceed the limit, requests are rejected with `429` until the next billing period, and the invoice never charges more than the limit. Workspace admins can view and change the limit (minimum $10) from the workspace's **Billing** page, and raising it above the current overage resumes requests immediately
- The Free tier has no payment method, so requests above its allowance are rejected with `429` instead

### Usage Alerts

Synapse alerts the workspace as usage grows, within a few minutes of the requests:

- **Included allowance:** at 75%, 90%, and 100% of the monthly request allowance, once per billing period. On Free, 100% is where requests start being rejected; on Pro and Team, it is where overage begins
- **Spending limit (Pro and Team):** at 75% and 90% of the hard spending limit, and when the limit is reached and requests pause. These alerts are also emailed to the billing contact

## Entitlements

Each tier includes a set of entitlements enforced by the gateway and API:

- **`api_access`** -- whether API requests are allowed
- **`max_requests_per_month`** -- included monthly requests (-1 = unlimited); a hard limit on Free, the overage threshold on Pro and Team
- **`overage_rate_cents:requests`** -- request overage rate in cents per 1K requests (Pro and Team only)
- **`max_api_keys`** -- API key creation limit (-1 = unlimited)
- **`max_input_tokens_per_request`** -- per-request input token cap
- **`max_output_tokens_per_request`** -- per-request output token cap
- **`smart_routing`** -- access to cost/quality/latency routing strategies
- **`stt_enabled`**, **`tts_enabled`**, **`image_gen_enabled`**, **`embeddings_enabled`** -- modality access
- **`analytics_retention_days`** -- how long usage data is retained
- **`team_rbac`** -- workspace roles and permissions
- **`byok_enabled`** -- bring your own provider keys

View your current entitlements in the [Synapse dashboard](https://synapse.omni.dev/dashboard/billing).

## Usage Metering

Every request through the gateway is metered:

1. **Input tokens** -- tokens sent to the provider
2. **Output tokens** -- tokens received from the provider
3. **Request count** -- incremented per API call
4. **Message count** -- number of messages in conversation

Usage is recorded asynchronously and never blocks request handling. Meter data flows to Aether for quota tracking and billing. The request count is the meter that request overage is billed from.

## Webhooks

Synapse receives entitlement updates from Aether via HMAC-signed webhooks:

- `entitlement.created` -- new subscription activated
- `entitlement.updated` -- plan changed or renewed
- `entitlement.deleted` -- subscription canceled

Plan changes take effect immediately. The billing cache is invalidated on each webhook event.

## Self-Hosted Billing

When self-hosting, billing integration is optional. Without Aether configured:

- All users default to a generous fallback quota
- BYOK mode works without any billing setup
- Usage events are still recorded locally in the database
- Set `BILLING_BASE_URL` to connect to your own Aether instance

See the [self-hosting guide](/products/synapse/self-hosting) for configuration details.
