Synapse exposes OpenAI-compatible and Anthropic-compatible endpoints. All endpoints accept JSON request bodies and return JSON responses.

<Callout type="info">
  Examples use `localhost:6000`, the Docker Compose host port. For binary installs, substitute `localhost:3000`.
</Callout>

## Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/v1/chat/completions` | POST | LLM chat (OpenAI-compatible, streaming) |
| `/v1/messages` | POST | LLM chat (Anthropic-compatible, streaming) |
| `/v1/models` | GET | List the models the calling key can use, with display names, the default, and prices |
| `/v1/embeddings` | POST | Generate text embeddings |
| `/v1/images/generations` | POST | Generate images |
| `/v1/images/edits` | POST | Generate images from reference images |
| `/v1/audio/transcriptions` | POST | Speech-to-text |
| `/v1/audio/speech` | POST | Text-to-speech |
| `/mcp/tools/list` | POST | List available MCP tools |
| `/mcp/tools/call` | POST | Execute an MCP tool |
| `/mcp/search` | GET | Search MCP tools by query |
| `/health` | GET | Health check |

## POST /v1/chat/completions

OpenAI-compatible chat completions endpoint. Supports streaming via `stream: true`. Request bodies (including inline base64 images) can be up to 32 MiB.

```bash
curl http://localhost:6000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-api-key" \
  -d '{
    "model": "claude-sonnet-4-20250514",
    "messages": [
      {"role": "system", "content": "You are a helpful assistant"},
      {"role": "user", "content": "Hello!"}
    ],
    "stream": false,
    "max_tokens": 1024
  }'
```

Response:

```json
{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "model": "claude-sonnet-4-20250514",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 15,
    "completion_tokens": 9,
    "total_tokens": 24
  }
}
```

### Reasoning effort

Set `reasoning_effort` (`none`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max`) to control how much a reasoning model thinks. It is sent to OpenAI-compatible upstreams as `reasoning_effort` (`max` becomes `xhigh`) and to Anthropic models as `output_config.effort` (`none` and `minimal` become `low`). Omit it to use the model's default.

## POST /v1/messages

Anthropic-compatible messages endpoint. Supports streaming via `stream: true`. Request bodies (including inline base64 images) can be up to 32 MiB.

```bash
curl http://localhost:6000/v1/messages \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-api-key" \
  -H "anthropic-version: 2023-06-01" \
  -d '{
    "model": "claude-sonnet-4-20250514",
    "max_tokens": 1024,
    "messages": [
      {"role": "user", "content": "Hello!"}
    ]
  }'
```

Response:

```json
{
  "id": "msg_...",
  "type": "message",
  "role": "assistant",
  "content": [
    {
      "type": "text",
      "text": "Hello! How can I help you today?"
    }
  ],
  "model": "claude-sonnet-4-20250514",
  "stop_reason": "end_turn",
  "usage": {
    "input_tokens": 10,
    "output_tokens": 9
  }
}
```

### Thinking and effort

`thinking` and `output_config` are passed through to Anthropic models unchanged, so you can set adaptive thinking, the thinking display, the effort level, or structured output:

```json
{
  "model": "anthropic/claude-opus-5-5",
  "max_tokens": 16000,
  "thinking": { "type": "adaptive", "display": "summarized" },
  "output_config": { "effort": "high" },
  "messages": [{ "role": "user", "content": "Prove it" }]
}
```

`output_config.effort` reaches OpenAI-compatible models as `reasoning_effort` (`max` becomes `xhigh`). Thinking tokens count as output tokens and are billed as output, whether or not a thinking block is returned. Thinking blocks are not included in gateway responses. Google and Bedrock upstreams ignore both fields.

## GET /v1/models

List the models the calling API key can use. The response is OpenAI-compatible, and each entry adds a `synapse` object so a model picker never hardcodes names, defaults, or prices.

```bash
curl http://localhost:6000/v1/models \
  -H "Authorization: Bearer your-api-key"
```

- A **product-scoped key** (issued for another Omni product) lists exactly that product's models, in the order the product's [model policy](/products/synapse/configuration#product-model-policies) declares them, with its default flagged
- **Any other key** lists every model the gateway serves

Response for a product-scoped key:

```json
{
  "object": "list",
  "data": [
    {
      "id": "anthropic/claude-sonnet-5-5",
      "object": "model",
      "created": 1763164800,
      "owned_by": "synapse",
      "synapse": {
        "display_name": "Claude Sonnet 5.5",
        "default": true,
        "context_window": 1000000,
        "credits_per_mtok": { "input": 400, "output": 2000 }
      }
    },
    {
      "id": "anthropic/claude-haiku-5-5",
      "object": "model",
      "created": 1763164800,
      "owned_by": "synapse",
      "synapse": {
        "display_name": "Claude Haiku 5.5",
        "default": false,
        "context_window": 1000000,
        "credits_per_mtok": { "input": 20, "output": 100 }
      }
    }
  ]
}
```

| Field | Description |
|-------|-------------|
| `id` | The value to send as `model` |
| `synapse.display_name` | Human-readable name for model pickers |
| `synapse.default` | Whether the model is the key's default, which `"model": "auto"` resolves to |
| `synapse.context_window` | Context window in tokens, or `null` when unknown |
| `synapse.credits_per_mtok` | Retail price per million input and output tokens in credits ($0.01 each), including the margin the key is billed at. `null` when the key is not billed for the model (bring-your-own-key, or a model with no managed price) |

Prices come from the same table the gateway bills with, so the listed price is what a request is charged per token. A prompt above a model's long-context threshold is billed at that model's higher long-context rate.

A product-scoped key that requests a model outside its list receives `400` with an `invalid_request_error` in the endpoint's own error format, before any provider call or charge:

```json
{
  "error": {
    "message": "model openai/gpt-4o is not available for this API key; GET /v1/models lists the models it can use",
    "type": "invalid_request_error",
    "code": null
  }
}
```

## POST /v1/embeddings

Generate text embeddings. Requires an [embeddings provider](/products/synapse/providers#embeddings-providers) configured.

```bash
curl http://localhost:6000/v1/embeddings \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-api-key" \
  -d '{
    "model": "text-embedding-3-small",
    "input": "Hello world"
  }'
```

Response:

```json
{
  "object": "list",
  "data": [
    {
      "object": "embedding",
      "index": 0,
      "embedding": [0.0023, -0.0091, ...]
    }
  ],
  "model": "text-embedding-3-small",
  "usage": {
    "prompt_tokens": 2,
    "total_tokens": 2
  }
}
```

## POST /v1/images/edits

Generate images from 1 to 16 reference images and a prompt. Requires an [image generation provider](/products/synapse/providers#image-generation-providers) configured. Accepts multipart form data (up to 64 MiB); every field is forwarded to the provider unchanged.

```bash
curl http://localhost:6000/v1/images/edits \
  -H "Authorization: Bearer your-api-key" \
  -F "model=openai/gpt-image-1.5" \
  -F "prompt=A sticker of a fox in the style of the references" \
  -F "image[]=@style-one.png" \
  -F "image[]=@style-two.png" \
  -F "quality=medium" \
  -F "size=1024x1024" \
  -F "input_fidelity=high"
```

| Field | Description |
|-------|-------------|
| `model` | Required. Managed keys support `gpt-image-1.5` and `gpt-image-1-mini` |
| `prompt` | Required |
| `image[]` | Required, 1 to 16 files |
| `mask` | Optional mask image |
| `quality` | `low`, `medium`, `high`, or `auto` |
| `size` | `1024x1024`, `1024x1536`, `1536x1024`, or `auto` |
| `n` | 1 to 10 (default 1) |
| `input_fidelity` | `high` or `low` |

Response:

```json
{
  "created": 1700000000,
  "data": [
    {
      "b64_json": "iVBORw0KGgo..."
    }
  ],
  "usage": {
    "input_tokens": 10050,
    "output_tokens": 1056,
    "total_tokens": 11106
  }
}
```

With a managed key, the request is checked against your credits before it runs and charged from the reported token usage, so reference images are billed as image input. A request your credits cannot cover returns `402`. With a BYOK key, the request uses your own provider key and is not charged.

## POST /v1/audio/transcriptions

Speech-to-text transcription. Requires an [STT provider](/products/synapse/providers#stt-providers) configured. Accepts multipart form data (up to 32 MiB).

```bash
curl http://localhost:6000/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.wav" \
  -F "model=whisper-1"
```

Response:

```json
{
  "text": "Hello, this is a test recording."
}
```

## POST /v1/audio/speech

Text-to-speech synthesis. Requires a [TTS provider](/products/synapse/providers#tts-providers) configured. Returns audio bytes.

```bash
curl http://localhost:6000/v1/audio/speech \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-api-key" \
  -d '{
    "model": "tts-1",
    "input": "Hello world",
    "voice": "nova"
  }' \
  --output speech.mp3
```

## POST /mcp/tools/list

List all tools available from configured [MCP servers](/products/synapse/mcp).

```bash
curl http://localhost:6000/mcp/tools/list \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-api-key" \
  -d '{}'
```

Response:

```json
{
  "tools": [
    {
      "name": "read_file",
      "description": "Read the contents of a file",
      "inputSchema": {
        "type": "object",
        "properties": {
          "path": { "type": "string" }
        },
        "required": ["path"]
      }
    }
  ]
}
```

## POST /mcp/tools/call

Execute a tool from a configured MCP server.

```bash
curl http://localhost:6000/mcp/tools/call \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-api-key" \
  -d '{
    "name": "read_file",
    "arguments": {
      "path": "/tmp/example.txt"
    }
  }'
```

Response:

```json
{
  "content": [
    {
      "type": "text",
      "text": "File contents here..."
    }
  ]
}
```

## GET /mcp/search

Search available MCP tools by query string.

```bash
curl "http://localhost:6000/mcp/search?q=file&limit=5" \
  -H "Authorization: Bearer your-api-key"
```

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `q` | string | yes | Search query |
| `limit` | integer | no | Max results (default: 10) |

Response:

```json
{
  "tools": [
    {
      "name": "read_file",
      "description": "Read the contents of a file",
      "inputSchema": {
        "type": "object",
        "properties": {
          "path": { "type": "string" }
        },
        "required": ["path"]
      }
    }
  ]
}
```

## GET /health

Health check endpoint. No authentication required. The gateway binary listens on port 3000 by default; Docker Compose maps host port 6000 to container port 3000.

```bash
# Docker Compose (host port)
curl http://localhost:6000/health

# Binary (default port)
curl http://localhost:3000/health
```

Response (plain text):

```
ok
```

## Per-call cost

Every billed LLM request reports what it cost. Non-streamed `/v1/chat/completions` and `/v1/messages` responses carry three headers:

| Header | Meaning |
|--------|---------|
| `x-synapse-cost-usd` | Retail amount charged in US dollars, after the product margin, rounded up to $0.0001 exactly as it is deducted |
| `x-synapse-credits` | The same amount in credits ($0.01 each) |
| `x-synapse-provider-cost-usd` | Upstream provider cost in US dollars, before the margin |

The same figures appear as a `synapse_cost` object on the response `usage`. Streamed requests carry it on the final usage: the usage chunk of an OpenAI-format stream (`choices: []`, `usage.synapse_cost`) and the `message_delta` event's `usage` in an Anthropic-format stream:

```json
"usage": {
  "prompt_tokens": 1000,
  "completion_tokens": 500,
  "total_tokens": 1500,
  "synapse_cost": { "cost_usd": 0.0142, "credits": 1.42, "provider_cost_usd": 0.0071 }
}
```

The cost covers every billed attempt of the request: a cached response is costed like a served one, a failed-over request reports the model that served it, and an escalated cascade reports both attempts. BYOK requests report zero (you pay your provider directly). Requests without a billing identity report no cost.

## SDK Compatibility

Synapse is compatible with the standard OpenAI and Anthropic SDKs. Point the SDK's base URL at your Synapse instance:

### OpenAI SDK (Python)

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:6000/v1",
    api_key="your-synapse-api-key",
)

response = client.chat.completions.create(
    model="claude-sonnet-4-20250514",
    messages=[{"role": "user", "content": "Hello!"}],
)
```

### OpenAI SDK (TypeScript)

```typescript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://localhost:6000/v1",
  apiKey: "your-synapse-api-key",
});

const response = await client.chat.completions.create({
  model: "claude-sonnet-4-20250514",
  messages: [{ role: "user", content: "Hello!" }],
});
```

### Anthropic SDK (Python)

```python
from anthropic import Anthropic

client = Anthropic(
    base_url="http://localhost:6000",
    api_key="your-synapse-api-key",
)

response = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Hello!"}],
)
```
