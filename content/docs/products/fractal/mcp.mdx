The Fractal MCP server exposes Fractal's deploy and operations surface to AI
assistants that speak the [Model Context Protocol](https://modelcontextprotocol.io).
Connect an MCP client (for example a coding assistant or agent) and the
assistant can list and inspect services, trigger deploys, read logs, manage
environment variables, and create scheduled jobs on your workspace through typed
tools.

## How it works

Fractal hosts the server at `https://mcp.fractal.omni.dev/mcp` over the
Streamable HTTP transport, so there is nothing to install. Your MCP client sends
your workspace API token with every request, the server forwards it to the
Fractal API, and every action runs with that token's access. The server stores
no credentials and keeps no sessions: each request is handled on its own.

## Get an API token

The server authenticates with a workspace API token (`ftk_...`). Create one in
the dashboard (open your workspace and select the **API Tokens** tab) or with
`fractal tokens create --name <label>`. Copy the secret when it is shown (it is
shown only once) and store it in your MCP client's secret configuration, never
in a file committed to Git. To keep an assistant to specific projects, create a
[scoped token](/products/fractal/api-tokens#restrict-a-token-to-projects).

## Client configuration

Add the server to your client's MCP configuration as a remote (HTTP) server,
passing the token in the `Authorization` header:

```json
{
  "mcpServers": {
    "fractal": {
      "type": "http",
      "url": "https://mcp.fractal.omni.dev/mcp",
      "headers": {
        "Authorization": "Bearer ftk_..."
      }
    }
  }
}
```

Clients name these fields slightly differently (some use `transport` or
`serverUrl`); the three values that matter are the URL, the HTTP transport, and
the `Authorization: Bearer <token>` header. A request without a token is
rejected with `401`.

## Tools

Tools take the project's **name** (`project`) and the service's name
(`service` or `name`). `list_projects` returns the project names.

| Tool | Access | Arguments | What it does |
|------|--------|-----------|--------------|
| `list_projects` | Read | `owner`, `limit`, `offset` (all optional) | List your projects with phase and service count |
| `list_services` | Read | `project`, optional `limit`, `offset` | List a project's services with status, source, build settings, and cron schedule |
| `get_service` | Read | `project`, `name` | Read one service: phase, current image, URL, conditions and last error, source, build settings (including `rootDir` and `watchPaths`), env, and schedule |
| `list_cron_services` | Read | `project` | List only the [scheduled jobs](/products/fractal/scheduled-jobs) in a project |
| `get_env` | Read | `project`, `service` | Read a service's environment variables. Secret-backed values are masked |
| `get_logs` | Read | `project`, `service`, optional `tailLines` (1 to 5000, default 200), `sinceSeconds` | Read a snapshot of recent logs per pod, newest pod first. Any project role can read logs. Returns no pods when the service is asleep or scaled to zero |
| `deploy_service` | Write | `project`, `service`, optional `environment`, `namespace` | Rebuild and redeploy a service (the same as `fractal deploy`). Needs the `developer` role or higher. Omit `environment` to redeploy every environment |
| `set_env` | Write | `project`, `service`, `env` (list of `{ name, value }` or `{ name, secret }`), optional `replace` | Set or update environment variables. Merges with existing variables unless `replace` is `true`. A `secret` value is stored write-only in a managed secret. Triggers a rolling update |
| `create_cron_service` | Write | `project`, `name`, `schedule`, `source` (`git: { url, branch }` or `image: { repository, tag }`), optional `buildMode`, `dockerfilePath`, `rootDir`, `watchPaths`, `command`, `args`, `env`, `environment` | Create a scheduled job from a Git repository or image |

`get_logs` returns a snapshot, not a live stream. For a live tail, use
`fractal logs <service> --follow`. `create_cron_service` sets the schedule but
not the [scheduling controls](/products/fractal/scheduled-jobs#controls)
(concurrency, time zone, history, retries); set those afterwards in the
dashboard.

Each tool calls the same API the dashboard and [CLI](/products/fractal/cli-reference)
use, so an assistant's actions are visible and auditable the same way.

## Security

- A token acts with your access across its workspace. Scope and expire tokens
  for automation, and revoke any that leak (see [API Tokens](/products/fractal/api-tokens)).
- Keep the token in your MCP client's secret store, not in a checked-in config
  file.
- Review what an assistant proposes before it runs a write tool; MCP clients
  surface each tool call for approval.
