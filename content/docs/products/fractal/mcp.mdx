The Fractal MCP server exposes Fractal's deploy and operations surface to AI
assistants that speak the [Model Context Protocol](https://modelcontextprotocol.io).
Connect an MCP client (for example a coding assistant or agent) and the
assistant can list and inspect services, trigger deploys, read logs, manage
environment variables, and create scheduled jobs on your workspace through typed
tools.

## How it works

Fractal hosts the server at `https://mcp.fractal.omni.dev/mcp` over the
Streamable HTTP transport, so there is nothing to install. Your MCP client sends
your workspace API token with every request, and every action runs with that
token's access. The server stores no credentials.

## Get an API token

The server authenticates with a workspace API token (a bearer credential). In
the dashboard, open your workspace, go to **API Tokens**, and create one. Copy
the secret when it is shown (it is shown only once) and store it in your MCP
client's secret configuration, never in a file committed to Git. See
[API Tokens](/products/fractal/api-tokens) for the full lifecycle.

## Client configuration

Add the server to your client's MCP configuration as a remote (HTTP) server,
passing the token in the `Authorization` header:

```json
{
  "mcpServers": {
    "fractal": {
      "type": "http",
      "url": "https://mcp.fractal.omni.dev/mcp",
      "headers": {
        "Authorization": "Bearer ftk_..."
      }
    }
  }
}
```

Clients name these fields slightly differently (some use `transport` or
`serverUrl`); the three values that matter are the URL, the HTTP transport, and
the `Authorization: Bearer <token>` header. A request without a token is
rejected with `401`.

## Tools

| Tool | Access | What it does |
|------|--------|--------------|
| `list_projects` | Read | List the projects in your workspace |
| `list_services` | Read | List a project's services with type and status |
| `get_service` | Read | Read a service's status and configuration |
| `list_cron_services` | Read | List [scheduled jobs](/products/fractal/scheduled-jobs) and their schedules |
| `get_env` | Read | Read a service's environment variables (secret values masked) |
| `get_logs` | Read | Read a service's recent logs |
| `deploy_service` | Write | Trigger a deploy of an existing service |
| `set_env` | Write | Set or update environment variables on a service |
| `create_cron_service` | Write | Create a scheduled job from a Git repository or image |

Each tool calls the same API the dashboard and [CLI](/products/fractal/cli-reference)
use, so an assistant's actions are visible and auditable the same way.

## Security

- A token acts with your access across its workspace. Scope and expire tokens
  for automation, and revoke any that leak (see [API Tokens](/products/fractal/api-tokens)).
- Keep the token in your MCP client's secret store, not in a checked-in config
  file.
- Review what an assistant proposes before it runs a write tool; MCP clients
  surface each tool call for approval.
