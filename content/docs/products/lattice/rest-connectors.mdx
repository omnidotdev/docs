---
title: REST Connectors
description: Federate REST APIs as subgraphs in a Lattice supergraph
---

Lattice federates more than GraphQL. A **REST connector** exposes a REST API to the graph as a subgraph: map its fields to HTTP requests, and Lattice plans and executes queries across it alongside your GraphQL subgraphs.

## How it works

A subgraph is backed by REST when it carries a `rest` block instead of a GraphQL `url`:

- **Composition.** `lattice compose` reads the subgraph's `schema` (its SDL) and composes it into the supergraph, so the planner knows the REST subgraph's types and fields.
- **Execution.** At query time the planner routes fetches to the subgraph like any other. The connector translates each subquery into HTTP calls: it interpolates field arguments into the path, adds query parameters, attaches headers, and shapes the JSON response back into GraphQL.

No HTTP introspection happens for a REST subgraph; its shape comes entirely from the `schema` you provide.

## Example

Describe the subgraph's shape in SDL:

```graphql
# schemas/petstore.graphql
type Pet {
  id: ID!
  name: String!
  status: String!
}

type Query {
  pet(id: ID!): Pet
  pets(status: String): [Pet!]!
}
```

Map its fields to the REST API:

```yaml
# lattice.yaml
supergraph:
  path: ./supergraph.graphql

subgraphs:
  petstore:
    schema: ./schemas/petstore.graphql
    rest:
      base_url: https://petstore.example.com
      headers:
        Authorization: "Bearer ${PETSTORE_TOKEN}"
      fields:
        pet:
          path: /pets/{id}
          select: /data
        pets:
          path: /pets
          query:
            status: status
```

Compose and run:

```bash
lattice compose --config lattice.yaml --output supergraph.graphql
lattice serve --config lattice.yaml
```

A client query now resolves over REST:

```graphql
query {
  pet(id: "7") {
    name
    status
  }
}
```

Lattice calls `GET https://petstore.example.com/pets/7`, reads `/data` from the response body, and returns it as `pet`.

## Mutations

Map a GraphQL mutation to a write method and send a JSON body with `body`, naming the argument whose value is the payload:

```yaml
subgraphs:
  petstore:
    schema: ./schemas/petstore.graphql
    rest:
      base_url: https://petstore.example.com
      fields:
        createPet:
          method: POST
          path: /pets
          body: input        # the `input` argument is sent as the JSON body
```

```graphql
mutation {
  createPet(input: { name: "Rex" }) {
    id
  }
}
```

Lattice sends `POST /pets` with `{"name":"Rex"}` and returns the response as `createPet`.

## Entity resolution

A REST source can resolve entities that other subgraphs reference by `@key`. Declare an `entities` resolver per type; the representation's key fields fill the resolver `path`:

```yaml
subgraphs:
  petstore:
    schema: ./schemas/petstore.graphql
    rest:
      base_url: https://petstore.example.com
      entities:
        Pet:
          path: /pets/{id}       # {id} comes from the entity's @key fields
          select: /data
```

When another subgraph yields a `Pet` by its key, Lattice calls `GET /pets/{id}` for each referenced entity and merges the result into the graph. A single `_entities` fetch resolves its representations in order, one REST call each.

## Mapping reference

| Field | Purpose |
| --- | --- |
| `base_url` | Base URL prepended to every field `path`. |
| `headers` | Static headers sent on every request. |
| `fields.<name>.method` | HTTP method. Defaults to `GET`. |
| `fields.<name>.path` | Path template appended to `base_url`. `{arg}` placeholders are filled from the field arguments. |
| `fields.<name>.query` | Query-string parameters, mapping a parameter name to a field argument name. A parameter is omitted when its argument is absent. |
| `fields.<name>.select` | Optional [JSON Pointer](https://datatracker.ietf.org/doc/html/rfc6901) selecting a sub-value of the response body as the field result. |
| `fields.<name>.body` | For write methods, the argument whose value is sent as the JSON request body. |
| `entities.<Type>` | An entity resolver (same shape as a field mapping) that fetches one `<Type>` by its `@key` fields. |

Arguments may be literals or GraphQL variables; variables are resolved before the request is built.

## Scope

REST connectors cover query fields, mutations, and federated entity resolution. On the roadmap:

- OpenAPI ingestion to generate the subgraph SDL and mappings from a spec.
- Response field mapping for upstreams whose JSON shape differs from the schema.
- Additional upstream protocols.
