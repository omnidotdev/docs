## Server

```yaml
server:
  listen: "0.0.0.0:4000"
  playground: true  # Enable GraphiQL at GET /
```

## Subgraphs

Fetch schemas from running subgraphs at compose time:

```yaml
subgraphs:
  aether:
    url: http://aether:4001/graphql
  warden:
    url: http://warden:4002/graphql
```

Use local schema files (useful for CI/CD or when subgraphs aren't running):

```yaml
subgraphs:
  aether:
    url: http://aether:4001/graphql
    schema: ./schemas/aether.graphql
  warden:
    url: http://warden:4002/graphql
    schema: ./schemas/warden.graphql
```

### Headers

Add headers for authenticated subgraph introspection during `lattice compose`:

```yaml
subgraphs:
  aether:
    url: http://aether:4001/graphql
    headers:
      Authorization: "Bearer ${SUBGRAPH_TOKEN}"
```

## REST Connectors

Federate a REST API as a subgraph. Declare the subgraph's GraphQL shape with a `schema` (used by `lattice compose`) and map its root fields to HTTP requests under `rest`. A REST subgraph needs no `url`:

```yaml
subgraphs:
  petstore:
    schema: ./schemas/petstore.graphql
    rest:
      base_url: https://petstore.example.com
      headers:
        Authorization: "Bearer ${PETSTORE_TOKEN}"
      fields:
        pet:
          path: /pets/{id}       # {id} is filled from the field arguments
          select: /data          # optional JSON Pointer into the response body
        pets:
          method: GET            # defaults to GET
          path: /pets
          query:
            status: state        # ?status=<value of the `state` argument>
```

At runtime the planner routes fetches to `petstore` like any subgraph. The connector interpolates arguments into `path`, adds the mapped `query` parameters, attaches `headers`, calls the upstream, and returns the JSON (optionally narrowed by `select`) as the field result.

| Field | Purpose |
| --- | --- |
| `base_url` | Prepended to every field `path`. |
| `headers` | Static headers sent on every request. |
| `fields.<name>.method` | HTTP method (defaults to `GET`). |
| `fields.<name>.path` | Path template; `{arg}` placeholders come from the field arguments. |
| `fields.<name>.query` | Query parameters, mapping a parameter name to an argument name. |
| `fields.<name>.select` | Optional JSON Pointer selecting a sub-value of the response body. |
| `fields.<name>.body` | For write methods, the argument sent as the JSON request body. |
| `entities.<Type>` | Resolver that fetches one `<Type>` by its `@key` fields, for federated `_entities` resolution. |

REST connectors cover query fields, mutations, and entity resolution. See [REST Connectors](./rest-connectors) for the full guide. OpenAPI schema generation is on the roadmap.

## Caching

Response caching via Valkey/Redis:

```yaml
cache:
  entity:
    enabled: true
    valkey_url: redis://localhost:6379
    default_ttl: 300
```

## Rate Limiting

Request rate limiting via Valkey/Redis:

```yaml
rate_limit:
  enabled: true
  valkey_url: redis://localhost:6379
  default:
    requests: 100
    window: 60s
```

## Traffic Shaping

Coalesce identical in-flight subgraph requests to reduce backend load:

```yaml
traffic_shaping:
  dedupe_enabled: true
```

When enabled, if multiple concurrent queries trigger the same subgraph fetch (same URL, query, variables, and operation name), only one HTTP request is sent. Other callers wait for the result of the first request.

## `@defer` Support

Lattice supports `@defer` in query plans. When a query contains deferred fragments, the response is returned as `multipart/mixed` with the initial data followed by deferred patches:

```
Content-Type: multipart/mixed; boundary=---
```

Deferred nodes are currently executed eagerly and merged into the response. The multipart transport encoding enables clients that support incremental delivery.

## Query Limits

Reject abusive operations before planning or execution:

```yaml
limits:
  max_depth: 15
  max_complexity: 1000
  max_aliases: 30
  max_body_size: 2mb
```

`max_depth` caps selection-set nesting, `max_complexity` the total field count, and `max_aliases` the number of aliased fields (a common amplification vector). `max_body_size` rejects oversized request bodies early (`kb`, `mb`, `gb` suffixes, or a plain byte count).

## Automatic Persisted Queries

Let clients send an operation's SHA-256 hash in place of the full query to save bandwidth:

```yaml
persisted_queries:
  enabled: true
  cache_size: 1000
```

On the first request for an unknown hash the gateway responds with `PersistedQueryNotFound`; the client retries with the query body and matching hash, the gateway verifies that the body hashes to the claimed value, stores it, and executes. Subsequent requests send only the hash. The store is bounded by `cache_size` (oldest entries evicted first), so untrusted clients cannot grow it without limit.

## Trusted Documents

Lock the gateway to a fixed set of operations. Set `require: true` with a `manifest`, and the gateway runs only the operations in that manifest, rejecting freeform queries and any operation outside the set:

```yaml
persisted_queries:
  enabled: true
  require: true
  manifest: ./operations.json
```

The manifest is a JSON object mapping each operation's lowercase hex SHA-256 to its document:

```json
{
  "b8e5...": "query Me { me { id } }",
  "4a1c...": "query Posts { posts { title } }"
}
```

At boot the gateway loads the manifest and verifies that every document hashes to its key, refusing a tampered or mislabeled manifest. At request time clients send the operation hash exactly as they would for Automatic Persisted Queries; an unknown hash returns `PersistedQueryNotFound`, and a request with no hash (a freeform query) is rejected with `PERSISTED_QUERY_REQUIRED`. No operation is registered at runtime, so the allowlist is exactly the manifest.

Trusted mode fails closed: if the manifest cannot be read or parsed, the gateway rejects every operation rather than falling open.

## Health

The gateway serves a `/health` liveness endpoint that returns `200 OK` with `{"status":"ok"}`. It is mounted outside the authentication and rate-limit stack, so orchestrator probes need no credentials.

## Environment Variables

Use `${VAR_NAME}` syntax for environment variable substitution in any config value:

```yaml
subgraphs:
  aether:
    url: ${BILLING_GRAPHQL_URL}

auth:
  jwt:
    jwks_url: ${JWKS_URL}
```
