---
title: Live Preview
description: Check your site at every size, move between pages, view its code, and download it
---

The preview panel shows your site as it stands after the latest turn. It runs in
an isolated frame, so nothing in the preview can affect the builder.

On phones, the builder shows one panel at a time: use the **Chat** and
**Preview** toggle in the header to switch. Sending a prompt switches to the
preview automatically.

## Device sizes

Use the size buttons in the preview toolbar to check your layout:

| Size | Width |
|------|-------|
| **Desktop** | The full width of the panel |
| **Tablet** | 820px |
| **Mobile** | 390px |

If a layout breaks at a smaller size, ask for a fix in chat, for example "polish
the layout for phones".

## Pages

A multi-page site shows a tab for each page above the preview. Select a tab to
view that page. Links between pages also work inside the preview: select a
navigation link and the preview moves to that page.

## Toolbar

| Control | What it does |
|---------|--------------|
| **View code** | Swaps the preview for the site's code; select it again to go back |
| **Reload preview** | Re-renders the current page |
| **Open preview in a new tab** | Opens the current page full size in a new browser tab |
| **Download as HTML (.zip)** | Downloads the whole site as a `.zip` of HTML files |

## View the code

**View code** shows the files Keystone publishes for the site, read only: each
page's HTML (`index.html` for the home page, `<page>/index.html` for the
others) and, for a page with a script, its script file under `_keystone/`.
These are exactly the files a [hosted site](/products/keystone/publishing)
serves and [GitHub Sync](/products/keystone/github-sync) commits. Pick a file
from the list (which shows each file's size) to open it in the code editor,
with line numbers and syntax colors that follow your light or dark theme.

Keystone publishes each page on one long line, so the code view lays it out
for reading and says **formatted for reading** above it. **Copy** copies the
whole file exactly as published, not the formatted view. The files refresh
after every turn and every restored version. Viewing the code never spends
credits; to change it, ask in chat.

## Share or reload a view

The builder keeps its view in the page address, so reloading or sharing the
link opens the same view: the preview size (for example `device=mobile`), the
page tab (`page=menu`), and the code view with its open file (`view=code` and
`file=menu/index.html`). Desktop, the home page, and the preview are the
defaults and are left out of the address.

## Download your code

**Download as HTML (.zip)** saves the whole site as a `.zip` named after the
site (for example `crumb-bakery.zip`), with every page
as a standalone HTML file laid out the way a static host serves it: the home
page at `index.html` and every other page at `<page>/index.html`. The download
is yours to keep, edit, or host anywhere, and it never spends credits.

<Callout type="info">
  [Integration blocks](/products/keystone/integrations) (live products, posts,
  and buy buttons) load live data in the preview and in the download too. The
  preview runs each page's script, so animation and 3D play there as they do
  on a [hosted site](/products/keystone/publishing#scripts-on-hosted-sites). A
  preview link shows a still version of the site instead.
</Callout>

Forms in the preview and in the download do not send anything: sending one shows
**Submissions arrive once your site is published.** See
[Forms](/products/keystone/forms).

## Follow-up suggestions

After each turn, one-tap suggestions such as **Add a contact form** or **Make it
bolder** appear under the chat. See [Building in Chat](/products/keystone/building).
