## Overview

Every Taproot instance can be a valid Apollo Federation v2 subgraph. Enable it in config:

```yaml
schema:
  federation: true
```

## What federation adds

| Feature | Description |
|---------|-------------|
| `@key` directives | Primary keys become `@key(fields: "id")` on entity types |
| `_service { sdl }` | Auto-generated SDL with federation directives |
| `_entities` resolver | Resolves entity references by key fields |
| `_Entity` union | Union of all entity types (auto-generated by async-graphql) |

## Entity resolution

When a federation gateway needs to resolve an entity reference (e.g. a `User` referenced by another subgraph), it sends an `_entities` query:

```graphql
{
  _entities(representations: [
    { __typename: "User", id: "user-123" }
  ]) {
    ... on User {
      name
      email
    }
  }
}
```

Taproot resolves this by looking up the entity by its primary key using the planner. Plugin `on_plan` hooks are applied to entity resolution queries, so RLS and other filters work.

## Composing with a gateway

Taproot subgraphs compose with any Apollo-compatible gateway. The gateway fetches Taproot's SDL via `{ _service { sdl } }` and composes it with other subgraphs.

## Multi-entity resolution

A single `_entities` query can resolve multiple entities of different types:

```graphql
{
  _entities(representations: [
    { __typename: "User", id: "user-1" },
    { __typename: "Post", id: "post-1" }
  ]) {
    ... on User { name }
    ... on Post { title }
  }
}
```

Each representation is resolved via the planner with a `Scan` filtered by the entity's key fields.
