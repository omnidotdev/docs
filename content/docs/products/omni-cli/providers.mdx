# Providers

Omni CLI supports multiple LLM providers through a unified interface, allowing you to switch between models from different vendors.

## Supported Providers

| Provider | Models | API Key Env |
|----------|--------|-------------|
| **[Synapse](/products/synapse)** | All models via unified routing | (none, local) |
| **Anthropic** | Claude 4, Claude 3.5, Claude 3 | `ANTHROPIC_API_KEY` |
| **OpenAI** | GPT-4o, GPT-4, GPT-3.5 | `OPENAI_API_KEY` |
| **Google** | Gemini 2.0, Gemini 1.5 | `GOOGLE_API_KEY` |
| **Groq** | Llama 3, Mixtral | `GROQ_API_KEY` |
| **Mistral** | Mistral Large, Medium, Small | `MISTRAL_API_KEY` |
| **Ollama** | Any local model | (none) |

## Default Configuration

By default, Omni CLI uses Anthropic's Claude:

```toml
[agent]
provider = "anthropic"
model = "claude-sonnet-4-20250514"
```

## Switching Providers

### Via Config File

Edit `~/.config/omni/cli/config.toml`:

```toml
[agent]
provider = "openai"
model = "gpt-4o"
```

### Via Environment

```bash
export OMNI_PROVIDER=openai
export OMNI_MODEL=gpt-4o
```

### Via TUI

Use the `/model` command:

```
/model gpt-4o
```

## Provider Configuration

### Anthropic

```toml
[agent]
provider = "anthropic"
model = "claude-sonnet-4-20250514"

[agent.providers.anthropic]
api_key_env = "ANTHROPIC_API_KEY"
# Optional: custom base URL
# base_url = "https://api.anthropic.com"
```

Available models:
- `claude-opus-4-20250514` (most capable)
- `claude-sonnet-4-20250514` (balanced)
- `claude-3-5-sonnet-20241022`
- `claude-3-5-haiku-20241022` (fastest)

### Synapse (Recommended)

Route through [Synapse](/products/synapse) for unified provider management. Synapse handles API keys, model routing, and provider dispatch — configure your keys once in Synapse and use any model from any provider:

```toml
[agent]
provider = "synapse"
model = "claude-sonnet-4-20250514"
```

Synapse is preconfigured as a default provider pointing at the hosted gateway (`https://gateway.synapse.omni.dev`). Run `omni auth login` to store a Synapse API key (or set `SYNAPSE_API_KEY`). For a self-hosted gateway, set `base_url` on `[agent.providers.synapse]`; provider keys are then configured in Synapse's own config file.

### Ollama (Local)

Run models locally with Ollama:

```toml
[agent]
provider = "ollama"
model = "llama3"

[agent.providers.ollama]
type = "openai"  # Ollama uses OpenAI-compatible API
base_url = "http://localhost:11434/v1"
# No API key needed
```

First, start Ollama and pull a model:

```bash
ollama serve
ollama pull llama3
```

## Multiple Providers

Configure multiple providers and switch between them:

```toml
[agent]
provider = "anthropic"  # Default
model = "claude-sonnet-4-20250514"

[agent.providers.anthropic]
api_key_env = "ANTHROPIC_API_KEY"

[agent.providers.openai]
api_key_env = "OPENAI_API_KEY"

[agent.providers.ollama]
type = "openai"
base_url = "http://localhost:11434/v1"
```

Switch at runtime:

```bash
# Use OpenAI for this session
OMNI_PROVIDER=openai OMNI_MODEL=gpt-4o omni
```

## Project-Specific Providers

Override the provider for specific projects in `.omni/config.toml`:

```toml
[agent]
provider = "anthropic"
model = "claude-opus-4-20250514"  # Use Opus for this complex project
```

## Token Limits

Configure max tokens per provider:

```toml
[agent]
max_tokens = 8192  # Default for all providers

[agent.providers.anthropic]
max_tokens = 16384  # Higher limit for Anthropic
```

## Knowledge Retrieval

When a persona has knowledge packs, the CLI ranks them per turn with semantic search. That needs an embedding model (and a small chat model that rewrites follow-up questions into standalone search queries). The CLI picks where those requests go from the keys you already have:

| Key available | Where retrieval requests go | Models |
|---------------|-----------------------------|--------|
| An OpenAI key on the `openai` provider (`OPENAI_API_KEY`) | Directly to OpenAI (or the `openai` provider's `base_url`) | `text-embedding-3-small`, `gpt-4o-mini` |
| A Synapse API key (`omni auth login` or `SYNAPSE_API_KEY`) | The Synapse gateway configured on the `synapse` provider, the same one chat uses (`<base_url>/v1/embeddings`) | `openai/text-embedding-3-small`, `openai/gpt-4o-mini` |
| Neither | Semantic search is off; knowledge is ranked by keyword search only | |

A Synapse API key is only ever sent to your Synapse gateway, never to a model vendor. Through the gateway, retrieval usage is metered like chat. To point retrieval at a self-hosted gateway, set `base_url` on the `synapse` provider:

```toml
[agent.providers.synapse]
base_url = "https://synapse.example.com"
```

## Cost Considerations

The TUI status bar and the `/cost` command show an estimated session cost, computed from token counts and list prices. It is a display-only estimate, not your bill: with Omni credits, the Synapse gateway meters and charges the real usage, and the CLI never records or reports usage itself.

Different providers have different pricing. For cost-sensitive work:

- Use **Groq** for fast, cheap inference
- Use **Ollama** for free local inference
- Use **Claude Haiku** or **GPT-3.5** for simple tasks
- Reserve **Claude Opus** or **GPT-4** for complex reasoning
