---
title: Transactional Email
description: Send receipts, notifications, and auth emails through Herald's idempotent send API and TypeScript SDK.
---

Transactional email covers the messages your application sends in response to something a user did: receipts, notifications, and auth emails such as verification and password resets. Herald sends them through a single idempotent endpoint that verifies the sending domain, signs with DKIM, and runs suppression checks before the message goes out.

## Send a single message

```ts
import { createHerald } from "@omnidotdev/herald";

const herald = createHerald({ apiKey: process.env.HERALD_API_KEY! });

await herald.emails.send({
  from: "you@yourdomain.com",
  to: "customer@example.com",
  subject: "Welcome, {{name}}",
  html: "<p>Hello {{name}} 👋</p>",
  variables: { name: "Ada" },
});
```

Use `{{variable}}` placeholders in the subject and body and pass their values in `variables`; Herald substitutes them at send time.

<Callout type="info">
  Sending a one-off marketing email rather than a receipt or notification? Pass `marketing: true` so Herald adds a one-click unsubscribe and a CAN-SPAM footer. See [one-off marketing sends](/products/herald/marketing-email#one-off-marketing-sends).
</Callout>

## Compose a message in the dashboard

To email one person without writing code, open **Compose** in the dashboard.

### Recipients

**To** takes one recipient, as a plain address or with a name (`Ada Lovelace <ada@example.com>`), and the address is checked before you can send. Select **Add Cc, Bcc, Reply-To** to add **Cc**, **Bcc**, and **Reply-To**.

### Write the message

The body is written in the same rich text editor as [broadcasts](/products/herald/broadcasts#write-a-broadcast): headings, bold and italic text, lists, links, and images. Images are uploaded to your workspace's media library, and every image needs alt text. An image hosted on another site can't be sent; replace it with an upload.

Workspace owners and admins have an **HTML** switch, marked **Admin**, to write raw HTML instead, which is sent exactly as written. Members always use the editor.

### Preview

The **Preview** tab shows the message exactly as it will be sent, including the branded layout when it is turned on in [Brand](/products/herald/brand) settings. It also shows the plain-text version, which Herald writes from your message unless you write one yourself. Values you add under **Variables** fill in tags like `{{name}}` in the preview as they will in the sent email; without them, tags show as written.

### Send now or later

Send the message right away, or turn on **Send later** and pick a future date and time to schedule it. Scheduled messages are listed under **Scheduled**.

<Callout type="info">
  A message from **Compose** is a one-off message, not marketing mail, so it carries no unsubscribe footer. To email your whole team, send a broadcast to the [team audience](/products/herald/audiences-and-segments#team-audience) instead.
</Callout>

Over the API, `sendMessage` takes the same choice of body as `bodyFormat`. See [messages](/products/herald/api-reference#messages) in the API reference.

## Attach files

Pass `attachments` to send files with a message, such as a receipt PDF or a signed document. Each attachment takes a `filename` and the file's `content` as base64:

```ts
import { readFile } from "node:fs/promises";

const pdf = await readFile("contract-signed.pdf");
const logo = await readFile("logo.png");

await herald.emails.send({
  from: "you@yourdomain.com",
  to: "customer@example.com",
  subject: "Your signed contract",
  html: '<p>Your signed contract is attached.</p><img src="cid:logo" alt="Logo" />',
  attachments: [
    {
      filename: "contract-signed.pdf",
      content: pdf.toString("base64"),
      contentType: "application/pdf",
    },
    {
      filename: "logo.png",
      content: logo.toString("base64"),
      contentType: "image/png",
      contentId: "logo",
    },
  ],
});
```

- `contentType` is optional; Herald infers it from the file extension when you leave it out.
- Set `contentId` to show an image inline, and reference it from the html as `cid:<contentId>`.
- Herald cleans up the filename it shows the recipient: it drops any folder path and characters that are unsafe in a filename.

Limits per message:

| Limit | Value |
| --- | --- |
| Attachments | 20 |
| Total size (before base64 encoding) | 25 MB |
| Blocked file types | Executables, scripts, installers, shortcuts, and disk images (for example `.exe`, `.bat`, `.js`, `.msi`, `.lnk`, `.iso`) |

A message over the size limit fails with `attachments_too_large` (HTTP 413). A malformed attachment fails with `invalid_attachment`, a blocked file type with `attachment_blocked`, and more than 20 files with `too_many_attachments` (all HTTP 422). Herald checks attachments before it records the message, so a refused send leaves nothing behind.

<Callout type="info">
  A scheduled send (a future `sendAt`) cannot carry attachments and fails with `attachments_not_schedulable`. Send the message at the time you want it delivered instead. Herald never stores attachment files: it passes them to the mail server and keeps only the message record.
</Callout>

## Send a batch

Send up to 100 distinct emails in one call. Each message succeeds or fails on its own:

```ts
const { sendMessages } = await herald.emails.sendBatch({
  messages: [
    { from: "you@yourdomain.com", to: "a@example.com", subject: "Hi", html: "<p>Hi</p>" },
    { from: "you@yourdomain.com", to: "b@example.com", subject: "Hi", html: "<p>Hi</p>" },
  ],
});

for (const result of sendMessages.results) {
  if (!result.ok) console.error(`message ${result.index} failed: ${result.code}`);
}
```

Each result reports its own `ok` status, `index`, and failure `code`, so a single bad address never blocks the rest of the batch.

## List and inspect messages

Every message and its lifecycle (delivered, bounced, complained, opened, clicked) lands in one searchable log. Browse it from the dashboard, or query it from the SDK:

```ts
const { messages } = await herald.emails.list({ first: 20 });
const detail = await herald.emails.get(messages.nodes[0].rowId);
```

## React to delivery events

Register a webhook to receive delivery events as they happen:

```ts
await herald.webhooks.create({
  url: "https://yourapp.com/herald",
  eventTypes: ["delivered", "bounced", "opened", "clicked"],
});
```

Delivery events also stream out as CloudEvents, so the rest of your Omni stack can subscribe and react without polling.

## Escape hatch

Every SDK method is a typed wrapper over the generated GraphQL client. For any operation the facade does not surface, drop down to the raw client:

```ts
herald.raw.sendEmail({ input: { /* ... */ } });
```
